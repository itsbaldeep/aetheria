# MILESTONE M5.5 — CLIENT UI/UX OVERHAUL ("make it feel like a game")
### Addendum to docs/BRIEF.md. Commit as docs/M5_5_UI_UX_OVERHAUL.md. This milestone is MANDATORY and blocks M6. Read fully before touching code.

---

## 0. Why this milestone exists (read this, agent)

Human playtest verdict on the current client: **"absolutely ugly, no-effort UI, I barely could find what to do — it didn't feel like a game."**

Root cause is structural, not carelessness: every acceptance criterion so far was verifiable by bots and unit tests, so protocol/logic quality is high while visual quality had **zero feedback signal**. This milestone fixes that permanently by (a) giving the dev loop eyes via an automated screenshot pipeline reviewed by the human, and (b) defining concrete, checkable UI standards.

**New standing rule (applies forever, add to AGENTS.md):** no client-facing change is DONE until its screenshots have been generated by `make screenshots`, published to the review gallery, and approved by the human in FEEDBACK.md. "Tests green" is no longer sufficient for anything the player sees.

## 1. The screenshot pipeline (build this FIRST — it is the milestone's foundation)

The VPS has no GPU or display. Run the real client under a virtual display with software rendering:

- Install: `xvfb`, Mesa with llvmpipe (`libgl1-mesa-dri`, `mesa-vulkan-drivers` or fall back to GL compatibility).
- Run: `xvfb-run -a godot4 --path client --rendering-method gl_compatibility --resolution 1920x1080 -- --screenshot-tour`
- Implement `client/tools/ScreenshotTour.gd`: when launched with `--screenshot-tour`, it walks a scripted tour and saves PNGs via `get_viewport().get_texture().get_image().save_png()`. The tour must cover **every reachable screen and UI state**, at minimum:
  1. Login (empty, filled, error state)
  2. Character select (0 chars, with chars, create dialog, name-taken error)
  3. World HUD default (in town; in field; in combat with target selected)
  4. Chat (each tab, long messages, system messages)
  5. Quest log open; quest tracker with 1 and with 5 quests; NPC dialog (accept + turn-in states)
  6. Death screen; level-up moment; skill bar with cooldowns mid-sweep
  7. Every window added later (inventory, trade, auction…) in filled + empty states
- For world/HUD states, the tour logs in with a dedicated `screenshot_bot` account (server already supports bots) and uses GM teleports to stage scenes deterministically.
- Output: `docs/screens/<git-short-sha>/NN_name.png` (1920×1080, also emit 960×540 webp thumbnails).
- Publish: `make screenshots` copies the latest set to the **admin server** as a gallery page — `admin.<domain>/screens` (behind existing admin auth): thumbnail grid, click for full size, dropdown to compare against any previous sha side-by-side.
- Wire into the loop: `make screenshots` runs after every client-facing work block and before requesting human review. Append one line to STATE.md: `screens: <sha> awaiting review`.

**Human review loop:** the human opens the gallery (works from a phone), then writes verdicts in FEEDBACK.md (`screens <sha>: login OK, HUD — skill bar too small, chat font unreadable…`). Agent folds feedback in before proceeding. Silence ≠ approval.

## 2. Art direction: heavy anime styling on a classic-MMO layout skeleton

Two-part rule:
- **Layout = classic MMO conventions** (this is what fixes "I couldn't find what to do"): player frame top-left, target frame beside it appearing on target; skill bar bottom-center (buttons 1–9, keybind labels, cooldown radial sweeps); chat panel bottom-left with tabs; minimap top-right with zone name; quest tracker under the minimap on the right edge; bags/menu buttons bottom-right; XP bar as a thin strip above the skill bar. Golden `!` above quest givers, `?` above turn-ins, both also on the minimap.
- **Skin = ornate anime fantasy**: decorated panel frames with corner ornaments, ribbon-style headers, glowing accents, character portraits in unit frames, stylized damage numbers. The *structure* is conservative; the *dressing* is flamboyant.

### Design tokens (create `client/ui/theme/tokens.gd` + one Theme resource; NOTHING may use Godot's default theme)
- **Palette:** deep indigo-night base `#1a1230`, panel fill `#241a3f` @ 92% opacity, gold ornament/border `#d9a441`, magic-cyan accent `#5fd4e8`, HP `#e8556d`, MP `#4f8de8`, XP `#b06fe0`, text-primary `#f3ecff`, text-muted `#9d92b8`, positive `#7ee081`, warning `#e8b54f`.
- **Type scale:** display font (existing Cinzel) for titles/headers only; body font (existing Exo 2) at 15 px base; sizes 12/15/18/24/34; never below 12 px; line-height ≥ 1.3. Damage numbers use a heavy display weight with outline.
- **Spacing scale:** 4/8/12/16/24 px only. Consistent 12 px panel padding. No ad-hoc margins.
- **Panels:** 9-patch (NinePatchRect / StyleBoxTexture) ornate frames — one master frame texture family (normal / bright / dark variants). Rounded 6 px inner content area.
- **States:** every button/slot has distinct normal/hover/pressed/disabled/focused styleboxes; hover always visibly responds (≤ 0.1 s tween).
- **Tooltips:** everything interactive has one (skills: name, cost, cooldown, range, description; items later). Styled panel, 0.4 s delay.

## 3. Game feel ("juice") — small, cheap, mandatory

- Floating combat text: damage pops at hit location (scale-in, drift up, fade; crits bigger + gold); XP gains green; heal green.
- Hit feedback: 0.1 s white flash on struck entity; slight target shake; brief hitstop (0.05 s) on player melee connects.
- Target ring: colored ground ring + soft outline on current target (red hostile / green friendly); nameplates with HP bars over entities, fading with distance.
- Cast bars (self under skill bar, target's on their frame); ground-AoE telegraphs already exist — restyle to glowing anime circles.
- Skill bar: radial cooldown sweep, keybind label, out-of-range/out-of-mana tinting, press-flash.
- Camera: smoothed follow (spring damping), slight FOV kick on Rush/Blink.
- Audio (CC0 — Kenney audio packs, freesound; log every file in CREDITS.md): UI click/hover, attack swings/impacts per class, level-up sting, quest-accept/complete chimes, death sting, ambient loop per zone, one town + one field music track (CC0/CC-BY — e.g. Kevin MacLeod with attribution). Master/music/SFX sliders in settings.
- Level-up moment: burst VFX + sting + "LEVEL 7!" banner. Quest complete: banner + chime. These moments are the game's heartbeat — make them feel rewarding.

## 4. Onboarding & discoverability (fixes "I barely could find what to do")

- First login ever (per character, server-flagged): 4-step contextual hint toasts — move (WASD), camera (RMB drag), target+attack, talk to the glowing NPC. Each dismisses on completion. No walls of text.
- The first quest giver gets an oversized beacon (light pillar + `!`) until the first quest is accepted.
- Active quest objective: direction chevron at screen edge + marker on minimap; tracker lines show live progress (`Boars slain 3/8`) and pulse on update.
- `H` opens a keybind/help panel; ESC opens the game menu (settings, logout, exit). Both discoverable via visible bottom-right buttons.
- Empty states never blank: empty quest log says "Find quest givers marked with ! in Havenport."

## 5. Acceptance criteria for M5.5 (all must pass)

1. `make screenshots` produces the full tour deterministically on the VPS and publishes the gallery; documented in runbook.
2. Zero default-Godot-theme controls anywhere (automated check: tour flags any Control resolving default theme, plus human eyeball).
3. All §2 layout elements present and functional; all §3 juice items implemented; all §4 onboarding items implemented (bot-verifiable ones bot-verified: hint flags, beacon flag, help panel toggles).
4. VRoid characters animated in-world with toon shading (blocked only if human hasn't supplied models — then everything else ships and this line moves to M6 entry criteria).
5. 60 fps at 1080p medium on integrated GPU (human-verified on laptop), no hitches from UI tweens.
6. **Human verdict in FEEDBACK.md: "looks and feels like a real game" (or itemized fixes, iterated until approval).** This is the gate for m5.5-complete. Then tag, then M6 — and M6+ client UIs (inventory/trade/auction/party) are built to THIS standard from day one, screenshots included.

## 6. Workflow & budget adjustments (token efficiency — the loop now runs on a paid/free hybrid)

- **Session-per-task, not one eternal session.** Start each work block as a FRESH OpenCode session: read AGENTS.md + STATE.md + current milestone doc, do ONE checklist item, test, screenshot, update STATE.md, commit, end. This kills the auto-compact → "continue" churn (compaction re-reads burn most of the budget) and makes any-model resumption safe. STATE.md was designed for exactly this — trust it.
- Model routing: cheap/free models for mechanical work (codegen, seeds, boilerplate, test scaffolds); the paid model (GLM-5.2 API) for UI layout code, shader work, architecture, and anything that failed once on the free model. Never let a free model churn >2 failed attempts on the same task — escalate to the paid model immediately; retry-loops are the biggest silent token sink.
- Keep responses/diffs small: no full-file rewrites when an edit suffices; never paste screenshots or binary content into context; reference gallery URLs instead.
